# Data sources

NeuroGrid's tests use two kinds of data: small synthetic fixtures that are part of the repository, and a
public test corpus that is loaded on demand and never committed.

## Synthetic fixtures (`tests/fixtures/synthetic`)

- Generated deterministically by `tools/gen_fixtures.py`; `python tools/gen_fixtures.py --check` fails if
  the committed files differ from a fresh generation.
- Licence: CC BY 4.0 (see `REUSE.toml`).
- The signals are sine waves with Gaussian noise. No fixture contains data of a person. The metadata of
  the BIDS fixtures (`bids_ok`, `bids_issues`), such as authors, electrode positions and head
  circumference, are synthetic test values. `bids_ok` says so in its README. `bids_issues` has no README
  on purpose, because it tests the validator finding `README_FILE_MISSING`; it is synthetic in the same
  way, as generated by `tools/gen_fixtures.py`.

## Public test corpus (`.local/corpus`, not versioned)

```bash
python tools/corpus.py fetch
```

```bash
python tools/corpus.py verify
```

- `fetch` loads the files from OpenNeuro and PhysioNet. `verify` works offline and checks every file
  against `tools/corpus_lock.json` (path, size, SHA-256).
- Which files are taken from each data set is defined in `tools/corpus_spec.json`.
- Checksums: for PhysioNet the lock repeats the published `SHA256SUMS.txt`. OpenNeuro publishes no file
  checksums, so these were recorded at the first download, together with the commit (hexsha) of the
  snapshot.
- Tests that need the corpus carry the pytest marker `corpus` and are not part of the default run:

  ```bash
  python -m pytest -m corpus
  ```
