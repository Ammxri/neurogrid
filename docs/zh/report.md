# 阅读报告 {#report}

`neurogrid report` 只根据 `results.json` 生成报告，文件为 `report.zh.html` / `report.en.html`，使用 `--format pdf`
时另有 `report.zh.pdf` / `report.en.pdf`。两种格式内容相同。HTML 文件是自包含的（嵌入字体、不链接到其他文件，内容
安全策略不加载任何资源）；PDF 为 A4 纸，封面和摘要为纵向，第 3–6 部分为横向。PDF 的每一页页脚都有固定声明、页码
“x / y”和页眉。

!!! note "固定声明"
    使用 NeuroGrid 进行的预检。不构成国家药品监督管理局（NMPA）法规意义上的符合性评价。

## 1 封面 {#cover}

数据集及其版本、已加载的规则包及其版本、来源状态和 SHA-256、日期（检查的基准日期 `as_of`，而非打印时间）、工具
版本和清单哈希值。如果加载了占位规则包，会有横幅说明其规则并非依据标准原文且不计入统计。使用 `report --config`
时，封面还显示 vault 的访问日志：条目数、链头哈希值和哈希链状态，均在本报告自身的访问事件之前读取
（[NeuroVault](vault.md#verify)）；请将链头哈希值记在 vault 之外，以便以后用 `vault verify --expect-head` 检查。
不指定 `--config` 时没有这一行，报告也不作任何记录。

## 2 摘要 {#summary}

每个阶段（采集、处理、标注、存储、访问）有一个信号灯、错误和警告的数量（含待补的证明材料）以及覆盖率。

| 信号灯 | 含义 |
|---|---|
| 红 | 至少一条错误级规则未通过，或错误级规则的证明材料待补 |
| 黄 | 警告级规则出现同样情况 |
| 绿 | 已加载规则包中没有未通过的错误级规则（警告级规则也没有上述情况） |
| 灰 | 该阶段没有规则得出“通过”“未通过”“例外”或“证明材料待补”的结果 |

绿色仅表示已加载规则包中没有规则未通过，不涉及这些规则包以外的任何内容。覆盖率（可自动或半自动检查的强制性
条款所占比例）只对来源状态为 `inventory` 或 `final` 且对应一项标准的规则包计算；对 `core`、`bids`、`gxdsl008` 和
占位规则包显示“n/a”。

表格上方的总体结论从不说数据集通过了占位规则包的检查。如果只加载了占位规则包，总体结论改为说明本报告未评价任何规则包；此时所有信号灯均为灰色。

## 3 按严重程度排列的结果 {#findings}

错误、警告和提示，每条都有规则 ID、条款、名称、状态、文件、通道、测量值、阈值（及其来源：检查项默认值、规则包或
`neurogrid.toml`）、时间段和原因。空单元格显示“–”并附原因，例如人工规则没有测量值时。时间段相对于记录开始时间；
针对整条记录的值显示“整条记录”，数据集层面的值没有时间段；最多列出 20 个时间段，并给出其数量和总时长。

状态：通过、未通过、例外（已说明理由）、不适用、无法检查（附原因）、证明材料待补。报告中每条规则最多显示 50 行；
最后一行写明其余检查结果的确切数量，并说明完整列表在 `results.json` 中（`findings`，按 `rule_id` 筛选）。通过的检查
按规则计数。占位规则包的检查结果在单独的“未评价”部分中。

M14 的规则没有逐条结果行。CORE-M14-01（知情同意）的区块按用途、状态和原因统计需要该用途的受试者（包括已通过的
受试者），不含受试者 ID 和知情同意版本；只要该规则有按受试者的结果，即使全部通过，也显示该区块。某个单元格少于 5 名受试者
时，每个用途只显示总数（小单元格规则），报告中也不再有其他取决于知情同意决定的数字：规则标题下的一行只给出需要某一用途的
受试者人数，附录中的规则概览只给出该规则结果的总数，摘要中的已通过检查不计入这些结果，严重程度标题只计未通过的结果。摘要中
的错误数、信号灯和退出码与其他规则一样包含这些结果。按受试者的结果在 `results.json` 中。附录中该规则的例外只显示数量，
不含受试者、用途和理由；即使已加载的规则包中都没有该规则（例如只加载 BIDS 规则包），也是如此。

CORE-M14-02（重新取得知情同意）在其严重程度分组中只有一行，指向第 3 部分末尾的“新风险后的重新取得知情同意”部分。该部分
以固定文字“根据风险登记册，可能需要重新取得知情同意——由伦理委员会决定。”开头，并对日期在基准日期当日或之前的每项风险
（每条规则最多 50 项，其后一句给出其余风险的数量）给出其 ID、日期和所涉用途、其记录需要所涉用途的受试者人数，以及这些
受试者按结果的分列：知情同意版本不低于风险要求的版本（通过）、低于该版本（未通过）、例外，或基准日期时没有有效的知情同意
（由 CORE-M14-01 判断）。任一风险中某一结果少于 5 名受试者时，每项风险只显示其受试者人数（小单元格规则）；此时附录中的
规则概览不显示该规则的任何数字，摘要中的已通过检查也不计入该规则。摘要中的警告数和信号灯与其他规则一样包含其未通过的结果。
受试者 ID、知情同意版本、风险要求的版本和风险描述从不出现；受试者名单在 `results.json` 中。没有风险登记册、没有日期在
基准日期当日或之前的风险或没有知情同意数据时，该部分说明为何没有表格。附录中该规则的例外只显示数量。

## 4 各记录指标 {#metrics}

各记录指标表（格式、采样率、时长、EEG 通道数、通过的检查以及 M06–M09 的数值）和小型分布图，每个指标每条记录一个值
（最差的通道）。M06/M09 的抽样情况有记录：记录时间中的各段、随机种子、分析的通道、电极位置、滤波。本部分还显示
数据集层面的结果：类别占比和人口学信息（每个单元格少于 5 名受试者时扣留）、数据划分以及重复组的数量。

## 5 人工证明材料 {#evidence}

依据 `evidence.yaml` 评价的每条规则，包括类型、状态、文件、文件检查、NeuroGrid 计算的 SHA-256、审核人、日期和备注
（含理由）。“证明材料已提交”是用户的陈述，NeuroGrid 不对其作评价；NeuroGrid 只检查文件存在、不是链接且与记录的哈希值
一致。文件（相对路径）、审核人、备注和理由按 `evidence.yaml` 中的原样显示，在原始数据文件夹中不使用 `--show-paths`
时也是如此；审核人请填写角色或姓名缩写，从不填写全名（[隐私](privacy.md#outputs)）。

## 6 附录 {#appendix}

已加载规则的概览、生效配置（已去除可能识别个人身份的路径）、被覆盖的阈值、有理由的例外（含理由、批准人角色和
有效期）、本次运行的提示、运行环境（Python、平台、依赖库）、关于 NeuroGrid 不设用户账户且文件的访问权限由操作系统
管理的说明、使用 `--config` 时关于访问日志链头哈希值的说明，以及固定声明。

## 证明材料汇编 {#dossier}

`neurogrid report --format dossier` 写出 `dossier.pdf`：一个由三部分组成的 PDF，始终包含两种语言，不受 `--lang`
影响。第 1 部分是中英双语目录：标题、数据集（名称、编号、版本）、基准日期、工具版本、`results.json` 文件的 SHA-256、
各部分在汇编中的页码范围、证明材料列表（规则、文件、状态、NeuroGrid 计算的 SHA-256 和 `evidence.yaml` 中记录的
SHA-256）、清单摘要（哈希值、状态、文件和不一致）以及 NeuroVault 摘要：访问阶段每条规则按状态的结果数，与附录 6.1
的计法相同（知情同意规则被扣留的细分只显示其总数），使用 `--config` 时还有封面上的访问日志一行。第 2 和第 3 部分是
中文和英文报告，与 `--format pdf` 打印的相同；它们保留自身的页码。每一页都有固定声明：目录页为两种语言，报告页为
该报告的语言。

证明材料汇编只包含两份报告所含的内容以及 `results.json` 中的计数：不含信号、不含知情同意记录，也不含报告所示之外的
受试者 ID。其元数据只有标题、NeuroGrid 和基准日期。每个部分都通过报告的 PDF 检查，合并后的文件再检查一次；相同的
`results.json` 得到相同的文件。`dossier.pdf` 可以作为[检查包](vault.md#export)中的一份报告。

## 假名 {#pseudonymity}

在原始数据文件夹中，记录以假名 ID 显示（`rec-<8 位十六进制数>` 或 `neurogrid.toml` 中的映射）；`check --show-paths`
显示真实名称。唯一的例外是第 5 部分中 `evidence.yaml` 的 `document`、`reviewer`、`comment` 和 `justification`
字段，它们按原样显示（[人工证明材料](#evidence)）。NeuroGrid 不对数据做假名化处理：ID 和文件名来自输入。报告中不含
原始信号、信号哈希值、原始年龄，也不含可识别身份的文件头字段的取值。
